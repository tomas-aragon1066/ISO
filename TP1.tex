\paragraph{1.a}
	
\begin{itemize}
	\item Mencione y explique las características más relevantes de GNU/Linux.


	\item GNU/Linux es un sistema operativo libre que surge de la combinación del núcleo Linux con el sistema GNU. 
	
	Está compuesto principalmente por un kernel, un sistema de archivos jerárquico y un intérprete de comandos. El kernel es monolítico modular. Es decir se comporta como un único programa en memoria, pero tiene capacidad de cargar y descargar módulos mientras se ejecuta. El kernel se distribuye bajo la licencia libre GPLv2.
	
	Es un sistema operativo multiusuario y multitarea escrito principalmente en C y soporta varias arquitecturas.
	
	El sistema de archivos provee un modelo de permisos basado en tres categorías, el usuario, su grupo y los demás.

\paragraph{1.c}

\begin{itemize}
	\item ¿Qué es GNU?
	
	\item GNU es un sistema operativo tipo Unix. desarrollado para el proyecto GNU y bajo el auspicio de la FSF. Formado principalmente de software libre bajo términos \textit{copyleft} como GPL. GNU significa \textit{GNU is not Unix}, que destaca la diferencia entre GNU y Unix, siendo el primero libre y el segundo privativo. El kernel del proyecto, GNU Hurd, no llegó a completarse. \paragraph{1.d}

\begin{itemize}
	\item Indique una breve historia sobre la evolución del proyecto GNU.
	
	\item Richard Stallman inicia el proyecto en 1983. En 1985 crea la FSF que proporcionará soporte técnico y legal al proyecto GNU. Para el 1990 se han creado GCC, Bash e Emacs y la mayor parte de bibliotecas y utilidades que conformarían el SO, pero no se tiene un kernel funcional. Durante los 80 el proyecto GNU evalúa, e intenta adaptar kernels existentes. A principios de los 90 se opta por adaptar Mach de la Universidad Carnegie Mellon, que se denominaría Hurd. Sin embargo, este se demoraría y su adopción es limitada. De forma autónoma empieza el desarrollo de un kernel por el informático finlandés Linus Torvalds en 1991. Torvalds adoptaría la licencia GPL para su proyecto en el año 1992. Esto precipita el desarrollo del kernel que tomaría el nombre Linux, y que da lugar a la adopción de este junto a las herramientas GNU integradas en un SO libre que predomina hasta hoy.
\end{itemize}

\paragraph{7.a}

\begin{itemize}

	\item Particiones: definición, tipos, ventajas y desventajas.
		
	Las particiones son divisiones lógicas de un medio de almacenamiento. El sistema operativo las trata como dispositivos independientes.
		
	Existen dos esquemas principales de particionado: \textbf{MBR} y \textbf{GPT}.
	\begin{itemize}
			\item \textbf{MBR}: soporta hasta 4 particiones primarias; para obtener más particiones se crea una partición extendida que contiene particiones lógicas. Está limitado a discos de hasta 2 TB.
			\item \textbf{GPT}: no tiene el límite práctico de 4 particiones primarias, soporta discos de gran tamaño, incluye una copia de seguridad de la tabla de particiones y utiliza CRC para detectar corrupción.
	\end{itemize}
		
	\textbf{Ventajas del particionado:}
	\begin{itemize}
		\item Aislamiento de fallos: si una partición se corrompe, las demás pueden permanecer intactas.
		\item Posibilidad de instalar múltiples sistemas operativos.
		\item Uso de diferentes sistemas de archivos según los requerimientos de cada partición.
	\end{itemize}
		
	\textbf{Desventajas del particionado:}
	\begin{itemize}
		\item Poca flexibilidad por tener un tamaño fijo.
		\item Posible desperdicio de espacio libre si las particiones no se dimensionan adecuadamente.
		\item Redimensionar particiones puede implicar riesgos o requerir herramientas específicas.
	\end{itemize}

\end{itemize}

\paragraph{8.a}
\begin{itemize}
	\item ¿Qué es el BIOS? ¿Qué tarea realiza?
	
	\item el BIOS de \textit{Basic I/O System}, es un programa que se ejecuta al arrancar una computadora x86 y se encarga principalmente de inicializar el hardware y cargar un gestor de arranque para que el SO tome el control.
	
	
	Primero realiza un POST, \textit{power on self test} que verifica cuales dispositivos tiene disponibles la computadora y su funcionamiento. 
	
	Configura los dispositivos básicos según la configuración almacenada en su memoria.
	
	
	Busca un dispositivo de almacenamiento que tenga un sector de arranque válido según su configuración
	
	
	lee el primer sector físico de disco y carga el gestor de arranque transfiriéndole el control.
	
	Durante el arranque y incluso después ofrece rutinas para E/S, que permiten interactuar con el teclado, pantalla y discos.
\end{itemize}



\paragraph{8.b}
\begin{itemize}
	\item ¿Qué es UEFI? ¿Cuál es su función?
	
	\item UEFI de \textit{Unified Extensible Firmware Interface} es un estándar que regula la interfaz entre el firmware de la plataforma, hardware, y el SO durante el arranque.
	
	Su función principal es la de inicializar el hardware y cargar el SO ofreciendo un entorno estándar que permita la comunicación entre el SO y el firmware empotrado.
	
	Por este motivo realiza las tareas:
	\begin{itemize}
		\item Un auto-diagnóstico parecido al de BIOS.
	
		\item Cargar los controladores de los dispositivos básicos.
	
		\item Leer la tabla de particiones GPT 
	
		\item Localizar y ejecutar el cargador de arranque, archivo .efi, dentro de la partición ESP.
	
		\item Ofrecer un entorno de pre-arranque, un intérprete de comandos.
	
	\end{itemize}
	
	
	Además, UEFI proporciona servicios de tiempo de ejecución, que permiten al sistema operativo seguir comunicándose con el firmware incluso después de haber tomado el control. Por ejemplo UEFI brinda la infraestructura necesaria para la interfaz ACPI, que permite al sistema operativo gestionar el consumo energético de los dispositivos y controlar los estados de suspensión del sistema.
	
\end{itemize}


\paragraph{8.c}
\begin{itemize}
	\item ¿Qué es el MBR? ¿Qué es el MBC?
	
		\item MBR de \textit{master boot record} es el primer sector físico de un medio de almacenamiento, encargado de cargar el SO y definir cómo está particionado el disco. Este sector de 512 bytes tiene tres partes:
		
		\begin{enumerate}
			\item MBC de \textit{master boot code}, ocupa los primeros 446 bytes y es el código que la BIOS carga en memoria y ejecuta al arrancar. Su función es: analizar la tabla de particiones, buscar la que es activa, localizar el sector de inicio de la partición activa, cargarlo en memoria y, finalmente, transferir el control a este código que ya es específico del SO.
			
			\item Tabla de particiones, ocupa 64 bytes, describe cómo está particionado el disco, tiene un máximo de 4 entradas y por ende ese límite de particiones primarias.
			
			\item Firma de arranque, que ocupa 2 bytes y sirve como indicador de que este disco es válido para arrancar.
		\end{enumerate}
	
	
\end{itemize}



\paragraph{8.d}
\begin{itemize}
	\item ¿A qué hacen referencia las siglas GPT? ¿Qué sustituye? Indique cuál es su formato.
	
	\item Hacen referencia a \textit{GUID Partition Table}. Un esquema de partición que reemplaza a MBR. En especial en sistemas con arranque EFI.
	
	Su formato incluye:
	
	\begin{enumerate}
		\item MBR de protección: mantiene compatibilidad.
		
		\item Cabecera GPT primaria: contiene la firma 'EFI PART', el tamaño de la tabla de particiones, el GUID del disco, la cantidad de entradas y un checksum. 
		
		\item Entradas de partición: cada una describe una partición con GUID único, tipo, LBA de inicio y fin y sus atributos.
		
		
		\item Cabecera GPT de respaldo
		
	\end{enumerate}
	
\end{itemize}



\paragraph{8.e}
\begin{itemize}
	\item ¿Cuál es la funcionalidad de un “Gestor de Arranque”? ¿Qué tipos existen?¿Dónde se instalan? Cite gestores de arranque conocidos.
	
	\item Un gestor de arranque tiene la tarea de localizar el SO en el disco, cargarlo en memoria y cederle el control. Entre sus funciones están:
	
	\begin{enumerate}
		\item Cargar el kernel, y una imagen de \textit{disco RAM}
		
		\item Pasar parámetros al kernel.
		
		\item Cargar y ejecutar aplicaciones \textit{.efi}.
		
		\item Presentar un menú con opciones de SO y versiones del kernel.
		
		
	\end{enumerate}
	
	En sistemas BIOS el gestor se instala en el MBR, mientras que en UEFI se instala en la partición EFI, \texttt{/boot/efi}.
	
	Existen varios tipos, avanzados como GRUB 2, o simples como LILO y Windows Boot Manager.
	
\end{itemize}



\paragraph{8.f}
\begin{itemize}
	\item ¿Cuáles son los pasos que se suceden desde que se prende una computadora hasta que el SO es cargado (proceso de \textit{bootstrap})?
	
	\item la computadora ejecuta la BIOS/UEFI.
	
	\item realiza un auto diagnostico, y carga controladores básicos y carga el gestor de arranque ya sea desde el MBR o la partición EFI.
	
	\item el gestor de arranque carga el kernel del SO, y a menudo un \textit{initrd/initramfs}.
	
	\item el kernel se inicializa y monta la raíz.
	
	\item se ejecuta el primer proceso, \textit{init/systemd}.
	
\end{itemize}


\paragraph{8.g}
\begin{itemize}
	\item Analice el proceso de arranque en GNU/Linux y describa sus principales pasos.
	
	\begin{enumerate}
		\item Encendido y ejecución de firmware.
		
		\item Auto diagnóstico e inicialización de hardware: se verifica el estado de memoria, discos, etc, se inicializan los controladores básicos de dispositivo y se define el orden de arranque.
		
		\item Localización y carga del gestor de arranque.
		
		\item Ejecución del gestor de arranque: GRUB carga en memoria el kernel \texttt{vmlinuz-}. Carga un disco RAM \texttt{initrd.img-}. Pasa parámetros al kernel, \texttt{root=/dev/sda1, ro, quiet}.
		
		\item Inicialización del kernel: se descomprime el kernel y empieza su inicialización, configura la gestión de memoria, detecta e inicializa dispositivos de hardware y carga el sistema de archivos raíz temporal mediante \texttt{initramfs}. Una vez cargados los controladores esenciales, se monta el sistema de archivos real y se realiza el cambio de raíz mediante \texttt{switch\_root}.
		
		
		\texttt{initramfs} contiene los drivers y herramientas esenciales que permiten montar el sistema de archivos real.
		
		\item Ejecución del primer proceso: se ejecuta el primer proceso de usuario, init o systemd. Tiene PID 1 y es el responsable de iniciar todos los procesos del sistema.
		
		\item Arranque de servicios y entorno de usuario: el sistema de inicio lanza servicios de red, cron, syslog, etc., terminales virtuales y si corresponde, el entorno gráfico. El sistema está listo entonces para iniciar sesión.
		
	\end{enumerate}
	
\end{itemize}


\paragraph{8.h}
\begin{itemize}
	\item ¿Cuáles son los pasos que se suceden en el proceso de parada (\textit{shutdown}) de GNU/Linux?
	
	
	\begin{enumerate}
		\item Inicio del apagado: el usuario ejecuta un comando de apagado, \texttt{shutdown -h now} o \texttt{systemctl poweroff} y el sistema de inicio recibe la orden.
		
		\item Notificación a los usuarios: un mensaje vía \texttt{wall} que advierte a los usuarios.
		
		\item Detención ordenada de los servicios: se ejecutan los scripts de parada en orden inverso que fueron iniciados. En systemd se detienen las unidades activas.
	
		\item Terminación de procesos de usuario: se terminan los procesos de los usuarios, cerrando sus sesiones y aplicaciones.
		
		\item Sincronización de datos: se ejecuta el comando \texttt{sync} para escribir en disco los datos pendientes de la caché.
		
		\item Desmontaje de sistemas de archivos: se desmontan todos, excepto el raíz, que se remonta como solo lectura.
		
		\item Detención de procesos restantes: se envía \texttt{SIGTERM} y si no responde, \texttt{SIGKILL}.
		
		\item Apagado de hardware: el kernel ejecuta rutinas de apagado de hardware como discos, puertos, etc. Finalmente el sistema se detiene, \texttt{halt} o \texttt{poweroff}.
	
	\end{enumerate}
	
\end{itemize}




\paragraph{8.h}
\begin{itemize}
	\item ¿Es posible tener en una PC GNU/Linux y otro SO instalado? Justifique.
	
	Si, cada SO puede instalarse en su propia partición o disco. En sistemas modernos con UEFI cada SO tiene su gestor de arranque en la partición EFI. Y el gestor de arranque, por ej. GRUB presenta un menú con las opciones disponibles.
	
\end{itemize}




\paragraph{9.a}
\begin{itemize}
	\item ¿Cómo se identifican los archivos en GNU/Linux?
	
	En GNU/Linux no existe el concepto de extensión de archivo. Un archivo se identifica por su contenido, tipo, es decir directorio, enlace, etc, y sus permisos. Herramientas como \texttt{file} permiten determinar el tipo.
	
\end{itemize}

	\item\texttt{man}: una interfaz para los manuales del sistema. Tiene la sintaxis básica es \texttt{man [seccion] palabra}, las secciones más comunes son del 1 al 9, y se provee el nombre de alguna utilidad, llamada al sistema, libc, etc. Por ej. \texttt{man 2 write} para llamadas al sistema. 	\item -w: da la ruta de la pagina del manual.
	\item -a: muestra todas las coincidencias en todas las secciones del manual en sucesión.
	\item -k: retorna las paginas del manual con nombre o descripción dados.
	
	Las páginas están guardadas en \texttt{/usr/share/man/} y el ejecutable en \texttt{/usr/bin/man}.

	
\end{itemize}
