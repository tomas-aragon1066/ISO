\paragraph{1.a}
	
\begin{itemize}
	\item Mencione y explique las características más relevantes de GNU/Linux.


	\item GNU/Linux es un sistema operativo libre que surge de la combinación del núcleo Linux con el sistema GNU. 
	
	Está compuesto principalmente por un kernel, un sistema de archivos jerárquico y un intérprete de comandos. El kernel es monolítico modular. Es decir se comporta como un único programa en memoria, pero tiene capacidad de cargar y descargar módulos mientras se ejecuta. El kernel se distribuye bajo la licencia libre GPLv2.
	
	Es un sistema operativo multiusuario y multitarea escrito principalmente en C y soporta varias arquitecturas.
	
	El sistema de archivos provee un modelo de permisos basado en tres categorías, el usuario, su grupo y los demás.

\end{itemize}

\paragraph{1.c}

\begin{itemize}
	\item ¿Qué es GNU?
	
	\item GNU es un sistema operativo tipo Unix. desarrollado para el proyecto GNU y bajo el auspicio de la FSF. Formado principalmente de software libre bajo términos \textit{copyleft} como GPL. GNU significa \textit{GNU is not Unix}, que destaca la diferencia entre GNU y Unix, siendo el primero libre y el segundo privativo. El kernel del proyecto, GNU Hurd, no llegó a completarse. Algunos componentes populares son \texttt{Bash, coreutils, gcc y glibc}.
\end{itemize}


\paragraph{1.d}

\begin{itemize}
	\item Indique una breve historia sobre la evolución del proyecto GNU.
	
	\item Richard Stallman inicia el proyecto en 1983. En 1985 crea la FSF que proporcionará soporte técnico y legal al proyecto GNU. Para el 1990 se han creado GCC, Bash e Emacs y la mayor parte de bibliotecas y utilidades que conformarían el SO, pero no se tiene un kernel funcional. Durante los 80 el proyecto GNU evalúa, e intenta adaptar kernels existentes. A principios de los 90 se opta por adaptar Mach de la Universidad Carnegie Mellon, que se denominaría Hurd. Sin embargo, este se demoraría y su adopción es limitada. De forma autónoma empieza el desarrollo de un kernel por el informático finlandés Linus Torvalds en 1991. Torvalds adoptaría la licencia GPL para su proyecto en el año 1992. Esto precipita el desarrollo del kernel que tomaría el nombre Linux, y que da lugar a la adopción de este junto a las herramientas GNU integradas en un SO libre que predomina hasta hoy.
\end{itemize}


\paragraph{1.e}

\begin{itemize}
	\item Explique qué es la multitarea, e indique si GNU/Linux hace uso de ella.
	
	\item La multitarea es la capacidad de un SO de conmutar y administrar múltiples tareas, es decir, procesos e hilos, de forma concurrente. GNU/Linux es multitarea. Específicamente usa multitarea apropiativa: el kernel puede interrumpir una tarea en ejecución para asignar tiempo de CPU a otra.
\end{itemize}

\paragraph{1.f}

\begin{itemize}
	\item ¿Qué es POSIX?
	
	\item POSIX es una norma de la IEEE que define una interfaz estándar del SO y su entorno, incluyendo al intérprete de comandos y programas de utilidades con el objetivo de soportar la portabilidad de aplicaciones, esta inspirada en interfaces, intérpretes de comandos y utilidades comunes en versiones de UNIX. Hoy en día muchos SO cumplen parcial o totalmente con algún estándar POSIX.
\end{itemize}

\paragraph{6.b}


\begin{itemize}
	\item ¿Cuál es la estructura básica de los File System en GNU/Linux? Mencione los directorios más importantes e indique qué tipo de información se encuentra en	ellos. ¿A qué hace referencia la sigla FHS?
	
	\item La estructura básica de un sistema de archivos en GNU/Linux es la de árbol. Con su raíz en \texttt{/}. 
	
	Sus directorios más importantes son:
		\begin{enumerate}
			\item \texttt{/bin}: a donde se almacenan los binarios de comandos accesibles a todos los usuarios.
			
			\item \texttt{/boot}: archivos estáticos que carga el gestor de arranque.
			
			\item \texttt{/dev}: archivos de dispositivos.
			
			\item \texttt{/etc}: configuración del sistema.
			
			\item \texttt{/home}: directorios de archivos de los usuarios.
			
			\item \texttt{/lib}: librerías compartidas y módulos del kernel.
			
			\item \texttt{/media}: donde se montan medios extraíbles.
			
			\item \texttt{/mnt}: donde se montan temporalmente sistemas de archivos.
			
			\item \texttt{/proc}: Sistema de archivos virtual que contiene información de los procesos en ejecución y del kernel en tiempo real 
			
			\item \texttt{/root}: home del superusuario.
			
			\item \texttt{/run}: datos de variables en tiempo de ejecucion.
			
			\item \texttt{/sbin}: archivos binarios del sistema.
			
			\item \texttt{/srv}: archivos de servicios provistos por el sistema.
			
			\item \texttt{/tmp}: archivos temporales.
			
			\item \texttt{/usr}: Almacena la mayoría de los programas, librerías, documentación y archivos de código fuente del sistema para los usuarios.
			
			\item \texttt{/var}: logs, etc.
		\end{enumerate}
		
	FHS, hace referencia a \textit{Filesystem Hierarchy Standard}, es un estándar que regula la ubicación de archivos y directorios en SO tipo Unix.  
\end{itemize}

\paragraph{7.a}

\begin{itemize}

	\item Particiones: definición, tipos, ventajas y desventajas.
		
	Las particiones son divisiones lógicas de un medio de almacenamiento. El sistema operativo las trata como dispositivos independientes.
		
	Existen dos esquemas principales de particionado: \textbf{MBR} y \textbf{GPT}.
	\begin{itemize}
			\item \textbf{MBR}: soporta hasta 4 particiones primarias; para obtener más particiones se crea una partición extendida que contiene particiones lógicas. Está limitado a discos de hasta 2 TB.
			\item \textbf{GPT}: no tiene el límite práctico de 4 particiones primarias, soporta discos de gran tamaño, incluye una copia de seguridad de la tabla de particiones y utiliza CRC para detectar corrupción.
	\end{itemize}
		
	\textbf{Ventajas del particionado:}
	\begin{itemize}
		\item Aislamiento de fallos: si una partición se corrompe, las demás pueden permanecer intactas.
		\item Posibilidad de instalar múltiples sistemas operativos.
		\item Uso de diferentes sistemas de archivos según los requerimientos de cada partición.
	\end{itemize}
		
	\textbf{Desventajas del particionado:}
	\begin{itemize}
		\item Poca flexibilidad por tener un tamaño fijo.
		\item Posible desperdicio de espacio libre si las particiones no se dimensionan adecuadamente.
		\item Redimensionar particiones puede implicar riesgos o requerir herramientas específicas.
	\end{itemize}

\end{itemize}

\paragraph{8.a}
\begin{itemize}
	\item ¿Qué es el BIOS? ¿Qué tarea realiza?
	
	\item el BIOS de \textit{Basic I/O System}, es un programa que se ejecuta al arrancar una computadora x86 y se encarga principalmente de inicializar el hardware y cargar un gestor de arranque para que el SO tome el control.
	
	
	Primero realiza un POST, \textit{power on self test} que verifica cuales dispositivos tiene disponibles la computadora y su funcionamiento. 
	
	Configura los dispositivos básicos según la configuración almacenada en su memoria.
	
	
	Busca un dispositivo de almacenamiento que tenga un sector de arranque válido según su configuración
	
	
	lee el primer sector físico de disco y carga el gestor de arranque transfiriéndole el control.
	
	Durante el arranque y incluso después ofrece rutinas para E/S, que permiten interactuar con el teclado, pantalla y discos.
\end{itemize}



\paragraph{8.b}
\begin{itemize}
	\item ¿Qué es UEFI? ¿Cuál es su función?
	
	\item UEFI de \textit{Unified Extensible Firmware Interface} es un estándar que regula la interfaz entre el firmware de la plataforma, hardware, y el SO durante el arranque.
	
	Su función principal es la de inicializar el hardware y cargar el SO ofreciendo un entorno estándar que permita la comunicación entre el SO y el firmware empotrado.
	
	Por este motivo realiza las tareas:
	\begin{itemize}
		\item Un auto-diagnóstico parecido al de BIOS.
	
		\item Cargar los controladores de los dispositivos básicos.
	
		\item Leer la tabla de particiones GPT 
	
		\item Localizar y ejecutar el cargador de arranque, archivo .efi, dentro de la partición ESP.
	
		\item Ofrecer un entorno de pre-arranque, un intérprete de comandos.
	
	\end{itemize}
	
	
	Además, UEFI proporciona servicios de tiempo de ejecución, que permiten al sistema operativo seguir comunicándose con el firmware incluso después de haber tomado el control. Por ejemplo UEFI brinda la infraestructura necesaria para la interfaz ACPI, que permite al sistema operativo gestionar el consumo energético de los dispositivos y controlar los estados de suspensión del sistema.
	
\end{itemize}


\paragraph{8.c}
\begin{itemize}
	\item ¿Qué es el MBR? ¿Qué es el MBC?
	
	\item ¿Qué es el MBR (Master Boot Record)?
	
	El MBR, o Registro de Arranque Maestro, es el primer sector físico de un dispositivo de almacenamiento (como un disco duro o una memoria USB). Ocupa exactamente 512 bytes y es la piedra angular del sistema de arranque en los sistemas con BIOS. Su función principal es iniciar el proceso de carga del sistema operativo y definir cómo está particionado el disco.
	
	Para cumplir su objetivo, el MBR contiene tres partes fundamentales:
	
	El Código de Arranque Maestro (MBC): Ocupa los primeros 446 bytes. Es un pequeño programa ejecutable que la BIOS carga en memoria para comenzar el proceso de arranque.
	
	La Tabla de Particiones: Ocupa 64 bytes. Describe cómo está dividido el disco. Como cada entrada de partición ocupa 16 bytes, solo puede haber un máximo de 4 particiones primarias.
	
	La Firma de Arranque: Son los últimos 2 bytes. Es un valor fijo (0x55AA) que actúa como una "marca" para que la BIOS sepa que el disco es válido para arrancar.
	
	¿Qué es el MBC (Master Boot Code)?
	
	El MBC, o Código de Arranque Maestro, es la primera parte del MBR y ocupa sus primeros 446 bytes. Actúa como el primer programa que se ejecuta. Su misión es:
	
	Analizar la tabla de particiones del MBR.
	
	Buscar la partición activa, la que está marcada para arrancar.
	
	Localizar el sector de inicio de esa partición activa y cargarlo en memoria.
	
	Transferir el control a ese nuevo código (el VBR, o Volume Boot Record), que es específico del sistema operativo y continuará el proceso de arranque.
	
	Relación y Función en el Arranque
	
	La relación es de continente y contenido: el MBR es el sector completo de 512 bytes y el MBC es una parte de él (los primeros 446 bytes).
	
	El proceso de arranque en un sistema con BIOS funciona así:
	
	Al encender el PC, la BIOS realiza el POST y busca un dispositivo de arranque.
	
	Cuando lo encuentra, lee el primer sector (el MBR) y lo carga en memoria.
	
	La BIOS ejecuta el MBC (el código de 446 bytes) que contiene ese MBR.
	
	El MBC busca la partición activa en la tabla de particiones.
	
	Una vez encontrada, carga el sector de arranque de esa partición (el VBR) y le transfiere el control.
	
	A partir de ahí, el VBR (que ya es específico de cada sistema operativo) se encarga de cargar el gestor de arranque (como GRUB o el gestor de Windows) y, finalmente, el sistema operativo.
\end{itemize}
